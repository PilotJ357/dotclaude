# dotclaude

Portable AI agent configuration. Skills, subagents and hooks authored **once** in `.claude/`, consumed by both **Claude Code** and **GitHub Copilot**.

No build step to use it. No symlinks. Two packages in the dependency tree.

## Why this exists

Most people maintain two copies of their agent config — one for Claude Code, one for Copilot — and they drift. They don't have to.

GitHub Copilot loads agent skills from `.github/skills/`, **`.claude/skills/`**, or `.agents/skills/`. Claude Code loads them only from `.claude/skills/`. That makes `.claude/skills/` the one directory *both* tools read natively, with zero configuration:

| Primitive | Claude Code | GitHub Copilot | Shared? |
|---|---|---|---|
| **Agent skills** | `.claude/skills/` | `.github/skills/`, **`.claude/skills/`**, `.agents/skills/` | ✅ **free** |
| Instructions | `CLAUDE.md` | `AGENTS.md` + `CLAUDE.md` (CLI); `.github/copilot-instructions.md` (VS Code) | ⚠️ partial |
| Subagents | `.claude/agents/` | `.github/agents/` only | ❌ |
| Slash commands | `.claude/commands/` | `.github/prompts/` — VS Code/VS only, **not CLI** | ❌ |
| Hooks | `.claude/hooks/` | — | ❌ Claude Code only |

So: **write everything as a skill**, keep it in `.claude/`, and generate thin pointer stubs into `.github/` for the two primitives that don't port. The stubs contain no substance, so they can't semantically drift — and CI fails if they're stale.

Detail and sources: [docs/portability.md](docs/portability.md).

## Layout

```
.claude/                  ★ source of truth — edit here
├── skills/<name>/SKILL.md    read natively by BOTH tools
├── agents/<name>.md          Claude Code subagents
├── hooks/                    Claude Code only (empty for now)
└── settings.json

.github/                  ⚙ generated by scripts/sync.mjs — do not edit
├── copilot-instructions.md
├── prompts/<name>.prompt.md
└── agents/<name>.md

AGENTS.md                 canonical instructions (CLAUDE.md just imports it)
scripts/sync.mjs          generate .github/; --check for CI
scripts/install.mjs       install skills into your home directory
tests/                    node:test validation suite
```

## Install

Requires Node 22+.

```bash
git clone https://github.com/PilotJ357/dotclaude.git && cd dotclaude
node scripts/install.mjs --dry-run
```

`--dry-run` prints exactly what would be written without touching anything. When it looks right:

```bash
node scripts/install.mjs
```

That copies `.claude/skills/*` into both `~/.claude/skills/` and `~/.copilot/skills/`, making every skill available to Claude Code and Copilot globally.

| Flag | Effect |
|---|---|
| `--dry-run` | Print the plan, write nothing |
| `--link` | Symlink instead of copy (needs Developer Mode on Windows) |
| `--force` | Overwrite existing skills |
| `--with-hooks` | Also install `.claude/hooks/` — **executes on your machine**, see below |
| `--claude-only` / `--copilot-only` | Restrict targets |

Or just use it per-project: clone into a repo and both tools pick up `.claude/skills/` with no install at all.

> [!WARNING]
> Hooks are shell scripts that agent runtimes run **automatically**. `--with-hooks` is opt-in for that reason. Read `.claude/hooks/` before using it. That directory ships no hooks in this revision — only its own README.

## Contributing

```bash
npm ci                # never `npm install`
npm run sync          # regenerate .github/ after editing .claude/
npm run validate      # sync freshness + tests + audit
```

Add a skill:

```bash
mkdir -p .claude/skills/my-skill && $EDITOR .claude/skills/my-skill/SKILL.md
npm run sync && npm test
```

See [CONTRIBUTING.md](CONTRIBUTING.md) and [docs/authoring.md](docs/authoring.md).

## Security

The dependency tree is deliberately **two packages** — `js-yaml` and its only child `argparse`, both pure JavaScript with no install scripts. Tests use Node's built-in runner. `.npmrc` sets `ignore-scripts=true`. Every GitHub Action is SHA-pinned, and CI holds no write permissions and references no secrets.

Rationale and threat model: [docs/security.md](docs/security.md). Reporting: [SECURITY.md](SECURITY.md).
