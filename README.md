# dotclaude

Portable AI agent configuration. Skills, subagents and hooks authored once in `.claude/`, consumed by both Claude Code and GitHub Copilot. No build step to use it, no symlinks, two packages in the dependency tree.

## Why

Copilot loads agent skills from `.github/skills/`, `.claude/skills/` or `.agents/skills/`. Claude Code loads them from `.claude/skills/`. That one directory is the intersection, so skills written there work in both tools with no configuration and no duplication. Hooks (`.claude/settings.json`) and — in VS Code — subagents (`.claude/agents/`) are also read natively.

Everything else is **generated** into `.github/` with the full body and runtime-appropriate frontmatter. Each skill is emitted twice — as a prompt file for `/<name>` in VS Code, and as an agent for `/agent <name>` in Copilot CLI, which has no prompt-file support. Subagents are emitted for the CLI and installed into both `~/.claude/agents/` and `~/.copilot/agents/`. CI fails if a generated file is stale, so a skill or subagent written once here is reachable from Claude Code, Copilot CLI and Copilot in VS Code.

The full per-runtime support matrix with sources, and the reasoning behind rejecting symlinks and CI copy jobs: [docs/portability.md](docs/portability.md).

## Layout

```
.claude/                     authored — edit here
├── skills/<name>/SKILL.md      loaded natively by both tools
├── agents/<name>.md            subagents; VS Code reads these too
├── hooks/                      scripts referenced from settings.json, empty
└── settings.json               hooks, read by all three runtimes; permissions

.github/                     generated by scripts/sync.mjs
├── prompts/<name>.prompt.md    skills → /<name> in VS Code
└── agents/<name>.agent.md      skills and subagents → /agent in the CLI

AGENTS.md                    canonical instructions; CLAUDE.md imports it
scripts/sync.mjs             generate .github/; --check for CI
scripts/install.mjs          install skills and subagents into your home dir
tests/                       node:test validation suite
```

`.github/workflows/`, `dependabot.yml` and `CODEOWNERS` are hand-written.

## Install

Node 24+.

```bash
git clone https://github.com/PilotJ357/dotclaude.git && cd dotclaude
node scripts/install.mjs --dry-run
```

`--dry-run` prints every write without performing one. Then:

```bash
node scripts/install.mjs
```

Copies `.claude/skills/*` into `~/.claude/skills/` and `~/.copilot/skills/`, and `.claude/agents/*` into `~/.claude/agents/`, making each skill available globally to both tools.

Subagents install by default, because the `done` skill spawns them by name. Both runtimes have a user-scope agents directory, so they go to `~/.claude/agents/<name>.md` and `~/.copilot/agents/<name>.agent.md` — the Copilot copy carries only the `name` and `description` frontmatter both tools read, since the optional fields differ.

| Flag | Effect |
|---|---|
| `--dry-run` | Print the plan, write nothing |
| `--link` | Symlink instead of copy (needs Developer Mode on Windows) |
| `--force` | Overwrite installed skills |
| `--uninstall` | Remove what the installer installed |
| `--no-agents` | Skip subagents |
| `--with-hooks` | Also install `.claude/hooks/` — executes on your machine |
| `--claude-only`, `--copilot-only` | Restrict targets |

Per-project use needs no install at all: clone into a repo and both tools read `.claude/skills/` directly.

Hooks are shell that agent runtimes run automatically, which is why `--with-hooks` is opt-in. This revision ships none — see [.claude/hooks/README.md](.claude/hooks/README.md).

## Security

Two-package dependency tree. `node:test` instead of a test framework. `.npmrc` sets `ignore-scripts=true`. No dependency version may be installed within 3 days of publication, enforced against the lockfile and mirrored by Dependabot cooldown. Actions pinned to full commit SHAs and restricted to GitHub-owned. CI has read-only token permissions and references no secrets. The installer copies data files only and refuses writes outside the two target roots.
